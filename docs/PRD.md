# Glow — Product Requirements Document (PRD)

## 1. Product name
**Glow — AI Skin Intelligence**

## 2. One-line description
Upload a selfie and get a dermatologist-grade AI skin report — 14 concern scores with visual masks, skin age, Fitzpatrick type, skin tone — plus a personalized routine and progress tracking.

## 3. Problem statement
People don't know what their skin actually needs. Skincare is a $150B+ industry built on guesswork: generic quizzes ("what's your skin type?") that rely on self-reported answers, not real skin data. Shoppers buy products that don't match their skin, waste money, and can't tell if anything is working. Dermatologist visits are expensive and slow.

## 4. Target users
- **18–35 skincare shoppers** who buy products online and want personalized recommendations
- **People with skin concerns** (acne, dark circles, wrinkles) who want to track improvement
- **D2C beauty brands' customers** (the model Perfect Corp already sells to Cetaphil, Decorté, and 800+ brands)

## 5. User pain points
- Don't know their skin concerns objectively
- Can't track whether a product/routine is working
- Overwhelmed by product choice; guess instead of choose
- No access to professional skin analysis (cost, time, embarrassment)

## 6. Proposed solution
**Glow** turns any phone camera into a skin-analysis tool:
1. Take/upload a selfie → **AI Skin Analysis** (14 concerns, each scored 0–100 with a visual detection mask) + **overall skin score** + **skin age**
2. Get **skin tone** + **Fitzpatrick skin type** (UV reactivity — the gold standard for sunscreen choice)
3. Receive a **personalized routine** — generated by rules from your actual scores (e.g., high wrinkle score → retinol + SPF recommendation)
4. **Track progress** — re-scan anytime, see your scores improve over time (the repeat-customer loop)

## 7. Product goals
- Give users objective, actionable skin data in under 30 seconds
- Make the "scan → recommend → repeat" loop real (the model the 800-brand network monetizes)
- Demonstrate multiple YouCam APIs working together (skin-analysis, skin-tone-analysis, fitzpatrick-scale-analyzer) — not a single-API wrapper

## 8. User stories
- As a user, I want to upload a selfie so I can see my skin's 14 concern scores.
- As a user, I want to see detection masks so I know *where* each concern is.
- As a user, I want my skin age + Fitzpatrick type + tone so I understand my skin profile.
- As a user, I want a personalized routine so I know what to buy/do.
- As a user, I want to re-scan later and see my progress so I know what's working.
- As a user, I want to share my results so I can show friends.

## 9. Functional requirements
- FR1: Upload or capture a selfie (front-facing, well-lit)
- FR2: Run YouCam skin-analysis (14 concerns) → scores + masks + overall + skin age
- FR3: Run YouCam skin-tone-analysis → skin/eye/lip/brow/hair colors
- FR4: Run YouCam fitzpatrick-scale-analyzer → skin type I–VI
- FR5: Generate routine recommendations from scores (rule engine)
- FR6: Save scan history locally (no account needed) and show progress charts
- FR7: Shareable result card (score + type + top concern)
- FR8: Demo mode when no API key (sample data replay)

## 10. User flow
```
Open app → Landing (problem + CTA)
  → Upload/capture selfie
  → "Analyze my skin" → AI runs (~15–30s)
  → Results dashboard: overall score, skin age, 14 concern tiles
  → Tap concern → mask overlay
  → Fitzpatrick + tone + colors panel
  → Personalized routine (AM/PM)
  → Save to history → progress chart on next scan
  → Share card
```

## 11. MVP scope (what must work in the demo)
- Upload selfie → real analysis (3 YouCam calls) → scores/masks/type/tone
- Routine engine (rule-based, deterministic from scores)
- History + progress in localStorage
- Demo mode (no key) so the demo never fails

## 12. Out of scope (intentionally not building)
- Accounts/auth, real product catalog, e-commerce checkout
- Multi-face, video analysis, HD analysis
- Backend database (schema provided; localStorage for MVP)

## 13. Non-functional requirements
- Latency: analysis ≤ 30s (upload+task+poll); UI responsive throughout
- Privacy: images processed in-memory; nothing stored server-side
- Works on mobile + desktop; modern browsers
- Unit costs respected: 16u (14-concern) + 20u (tone) + 10u (fitzpatrick) per full scan ≈ 46u → ~21 full scans per 1,000 units

## 14. Success metrics
- Demo converts (upload → report in <30s)
- ≥3 distinct YouCam APIs used
- Judge can explain the scan→recommend→track loop

## 15. Risks & assumptions
- Key credits run out → demo mode fallback + multi-key support
- Face quality rejection → guidance overlay + face-crop snapshots
- API latency → parallelize the 3 calls where possible, loading states
